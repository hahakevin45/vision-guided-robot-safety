# 安全層方法教學：從零開始的 CBF，到我們表現最好的方法

> All examples use representative VGR parameters: robot radius 0.23 m,
> max_v 0.15 m/s, margin/buffer 0.05–0.08 m, and motor time constant
> τ=0.08 s. Each section links the equations to repository code.

---

## 0. 共同框架：安全層到底是什麼

所有方法都做同一件事，只是「怎麼判斷危險」不同：

```
上層(Nav/遙控) --desired Twist(v,ω)--> [安全層 filter] --安全的 Twist--> 底層馬達
                                            ↑
                                 Observation(pose, wheel_feedback,
                                             pose_age_s, link_age_s)
```

- **輸入**：上層想要的速度命令 `desired = (v, ω)`，加上觀測
  （ArUco 位姿、輪速回授、資料新鮮度）。
- **輸出**：三態之一——
  - `PASS`：命令本身安全，原樣放行；
  - `MODIFIED`：有危險，改成最接近原意的安全命令；
  - `STOP`：無路可走或觀測不可信（位姿超過 0.5 s 沒更新），直接停。
- **共同第一步（看門狗）**：`pose_age_s` 或 `link_age_s` 超限 → STOP。
  任何方法都一樣——沒有可信的位姿，再聰明的數學都是瞎子。

介面定義在 `safety_sim/types.py`，六個方法都在 `safety_sim/filters/`。

## 1. CBF 基礎教學（Control Barrier Function，控制屏障函數）

### 1.1 核心思想：把「安全」寫成一個數字 h(x)

定義一個函數 h(x)，x 是車的狀態（位置、朝向）：

- **h(x) > 0**：安全（在允許區域內部）
- **h(x) = 0**：正好在安全邊界上
- **h(x) < 0**：出事了

我們的場景最簡單的 h 就是「到牆的淨距離」：

```
h = (車中心到牆的垂直距離) − 車半徑 − 安全裕度
  = d − 0.23 − 0.08
```

車在牆前 0.5 m 時，h = 0.5 − 0.31 = **0.19 m**。h 就是「還剩多少本錢」。

### 1.2 關鍵不等式：不是「離牆遠」，而是「靠近的速度要受控」

CBF 的靈魂是這一條約束：

```
ḣ ≥ −α · h        （α 是正常數，我們的實作取 α = 1.0）
```

ḣ 是 h 的變化率（車朝牆開，h 在減少，ḣ 是負的）。翻成白話：

> **你可以靠近牆，但「靠近的速率」不能超過「剩餘本錢的 α 倍」。**

直直朝牆開時 ḣ = −v（速度全花在接近牆上），約束變成：

```
−v ≥ −α·h   →   v ≤ α·h
```

用我們的數字算：

| 到牆距離 d | 本錢 h | 允許的最大速度 v ≤ 1.0·h               |
| ---------- | ------ | -------------------------------------- |
| 0.81 m     | 0.50 m | 0.50 m/s（比 max_v 大，不干預 → PASS） |
| 0.46 m     | 0.15 m | 0.15 m/s（正好卡到 max_v，開始干預）   |
| 0.41 m     | 0.10 m | 0.10 m/s                               |
| 0.36 m     | 0.05 m | 0.05 m/s                               |
| 0.31 m     | 0.00 m | 0 m/s（貼著安全線，只能停）            |

看出來了嗎？**允許速度隨剩餘距離線性遞減**，車會平滑地減速到牆前
停下，而不是撞到警戒線才急煞。α 越大煞車越晚越陡，α 越小越保守。
這就是為什麼 CBF 類方法的 min_clearance 穩定落在 margin 附近；
GS1 模擬結果為 0.18 m，呈現「貼邊但不越界」的特性。

### 1.3 差速車的麻煩：不能側移，怎麼辦？

差速車只有 (v, ω) 兩個控制量，不能橫著走。若 h 只跟位置有關，
ω 根本不出現在 ḣ 裡，約束管不到轉向。標準技巧是**前視點（lookahead）**：
不看車中心，看車頭前方 l = 0.10 m 的一個點 p：

```
ṗ = v·(車頭方向) + l·ω·(垂直方向)
```

這個點的速度同時含 v 和 ω，於是約束變成對 (v, ω) 的線性不等式：

```
a_v·v + a_ω·ω ≥ −α·h      （每面牆一條）
```

幾何上這是 (v, ω) 平面上的半平面。我們的實作
（`safety_sim/filters/cbf.py` 的 `_build_constraints`/`_project`）
不用 QP solver，直接把 desired 命令逐條**投影**到半平面交集上——
純解析，單步遠低於 5 ms。投影後可行集是空的 → STOP。

### 1.4 baseline CBF 的著名 bug：倒車盲區

前視點在**車頭前方**。倒車時車是屁股先走，真正會撞牆的是車尾，
但約束還是建在車頭前 0.10 m 的點上——幾何符號整個不對，約束
可能「看起來滿足」而車尾直插牆裡。可重現比較矩陣將這類倒車失效
保留為 baseline 對照；後續方法必須通過相同鑑別情境。
保留原樣作為對照組。

### 1.5 ICCBF：加上「煞車距離」的 CBF（我們的第 4 名，nominal 域最佳升級）

論文：_Safe Control Synthesis via Input Constrained Control Barrier
Functions_（IEEE CDC，arXiv:2104.01704）。實作 `safety_sim/filters/iccbf.py`。

baseline 假設車想停就能瞬間停，但真車馬達有 τ=0.08 s 延遲、
減速度上限 a_max。ICCBF 把「煞停需要的距離」直接從本錢裡扣掉：

```
h_iccbf = h − v_toward² / (2·a_max)
```

`v_toward` 是朝牆的速度分量。用我們的數字：v = 0.15 m/s、
a_max = 0.5 m/s² → 煞車距離 = 0.15²/1.0 = 0.0225 m。本錢少了
2.25 cm，等於自動把干預線往外推一個煞車距離——速度越快推越遠。

**同時它修了倒車盲區**：`v_toward = max(0, −ḣ)` 對雙向都成立
（`iccbf.py:55`），不管前進倒車，只要在接近牆就有約束。
這 11 行就是將來修 baseline 的移植來源。

## 2. 表現最好的方法教學

兩輪流水線（arXiv 輪＋IEEE 輪）總排名前二：

### 2.1 第一名：gf_dwa（Geofence Dynamic Window Approach）

- **論文**：_GPDF-DWA_（arXiv:2504.03260），我們改成 geofence 簡化版
- **實作**：`safety_sim/filters/gf_dwa.py`
- **成績**：包絡 756/864 全場最大、零碰撞；代價是六方法中最保守

**思想**：CBF 是「算出安全條件再投影」，DWA 反過來——
**「把附近能做的動作全部試一遍，挑不會撞的裡面最像你想要的」**。
是模擬預演式（rollout）的代表。

每個 tick 做四步：

1. **動態窗口**：從輪速回授讀目前 (v₀, ω₀)，一個控制週期內
   物理上到得了的速度範圍是 `v₀ ± a_max·dt`（我們 a_max=0.5、
   dt=0.05 s → 窗口寬 ±0.025 m/s），再夾進 ±max_v。
   **窗口包含負 v**——倒車天生被覆蓋，這是它沒有倒車盲區的原因。
2. **採樣**：窗口內取 7×7 = 49 個候選 (v, ω)。
3. **預演（rollout）**：每個候選用單車模型往前模擬 10 步 × 0.1 s
   （等於預看未來 1 秒的軌跡），軌跡上任何一點侵入
   「geofence − 車半徑 − margin」→ 該候選直接淘汰。
4. **打分**：活下來的候選算成本
   `J = q_col·(1/最小淨空) + q_ref·‖候選 − desired‖`
   （q_col=0.1、q_ref=1.0）——又要離牆有餘裕、又要貼近原命令，
   取最小者輸出。desired 自己活著就必須選 desired（→ PASS）。

**為什麼包絡最大**：它不依賴任何解析幾何假設，暴力預演對噪聲、
低更新率、怪角度全都魯棒——「未來 1 秒會不會撞」比「此刻的
梯度條件」更難被極端參數騙。

**為什麼最保守**：49 個候選裡只要 rollout 接近邊界就淘汰；高噪聲下
位姿抖動可能使整個窗口被拒絕，因此會以卡停換取安全。

**Implementation note**：採樣式方法可能選到極慢但非零的爬行候選。
公開實作將 |v|<0.03 且 |ω|<0.1 的候選吸附為真正停止，避免語意上
「沒撞但永遠停不下來」的結果。
教訓：**採樣式方法的「最優候選」可能是語意上的垃圾**，要加語意層。

### 2.2 並列首選：safe_apf（Safe Artificial Potential Field）

- **論文**：_Safe Artificial Potential Field — Novel Local Path
  Planning Algorithm Maintaining Safe Distance From Obstacles_
  （IEEE Robotics and Automation Letters）
- **實作**：`safety_sim/filters/safe_apf.py`
- **公開矩陣**：`safe_apf` 通過 S1–S7；full-field `safe_apf_new`
  另外通過 S8 障礙繞行。

**思想**：把環境想成一個力場——**牆推你，目標拉你**，車順著合力走。
傳統 APF 的斥力是漸近的（越近越大但沒有硬保證）；這篇論文的貢獻
是改造斥力形狀，**數學上保證維持 d_safe 安全距離**，這也是它敢叫
"Safe" APF 的原因。

每個 tick（對照 `_apf_command`）：

1. **吸引力**：desired 命令的方向，大小 |v|。
2. **斥力**：對每面牆算垂直距離 d 和法向量，力的大小分三段：

   ```
   d ≥ influence（影響圈外）      → 0，完全不管
   d_safe < d < influence         → max_v · rel²（二次平滑上升）
   d ≤ d_safe（侵入安全距離）     → max_v（滿斥力，最強推離）
   ```

   注意第三段：**侵入 d_safe 後斥力是常數滿格**，不是無限大——
   這保證輸出永遠有界（真車馬達做得到），同時「滿斥力 ≥ 任何
   吸引力」保證淨力向外。
3. **合力 → 命令**：合力方向就是目標朝向 θ*，
   `ω = k_θ·wrap(θ* − θ)`（k_θ=2.0）轉過去；速度按朝向誤差縮放
   ——誤差超過 90° 先原地轉不前進，對準了才給速度。
4. **倒車**：desired v<0 時把「運動朝向」取 θ+π（車尾向），
   同一套公式直接生效（`travel_theta`，`safe_apf.py:107`）。

**為什麼它是均衡點**：計算是 O(牆面數) 的純幾何，單步 0.05–0.3 ms
（gf_dwa 要 49 候選 × 10 步 rollout，貴一個數量級）；包絡幾乎
追平 gf_dwa；淨空卻更貼邊（0.229 vs 0.27）——同樣安全下少浪費
4 cm 工作空間。在樹莓派 CPU 預算下，這個組合非常划算。

**弱點**：勢場是「當下的力」，沒有預演未來——極端噪聲下
（噪聲 0.15 m＋4 Hz）位姿跳動會讓力方向亂抖，它的 126 個掃描
失敗都是這種近牆情境（淨空一度低於 0.05 m），但從沒撞過。
